# Personal Brand System as an optional input

## Ownership
PBS owns its accepted identity and brand records. Strategic Plan owns GRIT, annual focus, objectives, measurements, reflection, and planning decisions. Reuse PBS through a dated source reference plus a snapshot of the wording/style used. This preserves annual history without creating two competing identity authorities.

The integration is optional and read-only by default. Without PBS, develop the needed foundation directly in the planning package. A plan can be useful before any branding is complete.

## Discover only the relevant material
Use the person's identified personalized PBS package, not the generic standard or another person's package. If the location is unknown, ask where their package is after checking relevant workspace context. Read its entrypoint and relevant file index, then only the records needed. A missing expected filename is not a missing capability; versions may store visual guidance in the KB or accepted outputs.

Current PBS conventions to check, without assuming they exist in every version:
- `references/integrity-register.json`: canonical language IDs `purpose` and `personal-tenets`, exact text, version, source, disclosure, approval status.
- `references/personal-brand-kb.md`: Identity, Expression, personal success, boundaries/capacity, Evolution. Use only material relevant to planning.
- `references/asset-index.md`: identifies current accepted assets and versions. An index alone does not prove wording approval.
- Accepted purpose/tenets assets, voice guide, visual style guidance, and source materials identified by those records.

Do not use the generic PBS template's contents as personal facts. Do not import the entire biography, contact information, relationship records, or private stories simply because access exists.

## Input mapping
| PBS input | Planning use | Treatment |
|---|---|---|
| Accepted Purpose | Stable planning foundation and alignment check | Reuse exact wording; ask whether it still holds for this year |
| Accepted personal Tenets | Decision principles and tradeoffs | Reuse exact set; do not silently compress to 2–5 |
| Vision/aspirations | Candidate material for GRIT | Draft a GRIT for review; a brand vision is not automatically an accepted GRIT |
| Personal success/goals | Candidate annual TOs | Reassess relevance, baseline, measurement, deadline, and capacity |
| Boundaries, interests, lessons | Reflection and feasible choices | Preserve context; do not turn every interest into a goal |
| Accepted voice guidance | Interview summaries and drafted explanations | Preserve exact canonical statements; tone changes do not authorize rewrites |
| Accepted personal visual direction | HTML plan and exported visuals | Reuse colors, typography, available assets, and restrictions for the intended context |

## Carry a small source record
For each reused item record: input ID/type; source package locator; source record ID and version; source date; imported date; exact snapshot or asset reference; approval/disclosure status; planning review decision; affected plan IDs. Private locators belong only in the personal package. Copy necessary permitted assets there if portability is needed; keep attribution and usage restrictions.

Confirmed source wording is eligible for reuse; draft source wording remains a labeled candidate until reviewed. Ask one concise confirmation of continued fit rather than repeating PBS discovery. Keep Purpose and Tenets independently reviewable. Existing accepted tenets outside the planning default of 2–5 require a deliberate decision, not an automatic rewrite.

## Visual input rules
Determine whether the chosen style is the personal brand, company brand, or a deliberate combination. PBS dashboard UI colors are not automatically personal brand colors. Use accepted fonts with available fallbacks; retain readable contrast and clear status labels. No logo or remote font download is required. Missing visuals should fall back to the shared template style without blocking planning. Style preference does not grant asset rights or public publishing approval.

## Changes and conflicts
At a requested refresh, annual review, or discovery of a source change, compare source versions/content with the imported snapshot. Report what changed and which current outputs may be affected. Keep the last accepted planning snapshot until the person reviews the change. Do not rewrite prior-year plans.

If strategic planning reveals a revised Purpose or Tenets, save it as a proposed revision and offer a specific PBS update. When the user requests that update, follow PBS's independent review/version rules, then refresh the planning reference. No automatic two-way synchronization.

Standard method releases must never contain personal imports. Test this integration with synthetic or blank records, not copied personal packages.
