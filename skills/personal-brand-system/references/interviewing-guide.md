# Progressive interview — produce, then deepen
Version 0.5.0 | 2026-10-13
## Start
For a first-time leader, use [the short kickoff](kickoff-guide.md) before discovery. Start warmly, explain the value and living asset, offer the dashboard with opening instructions and ask one easy first question; adapt or skip the welcome for experienced and returning leaders. No preparation is required.
Read current KB, state and accepted assets. Explain the current phase and next deliverable. Offer Develop my brand or Help me do a task. Ask 1–3 useful questions, not a questionnaire dump. No forced complete biography before useful work.
## Foundation sprint
Establish intended outcomes, audience, contribution, 1–2 lived examples, boundaries/capacity and voice direction. Produce a first profile as soon as these are sufficient. Initial planning estimate: first useful draft after about 30–45 active minutes where inputs permit; this is a revised target to test, not a guarantee. Fuller baseline may take 3–5 hours over sessions; the pilot has not completed it yet.
## Breadth and depth controls
Default to one question at a time. Before each follow-up, identify the specific gap it will resolve for the next useful output. If there is no material gap, draft or move on.

A topic means a substantive subject, such as the current role, regardless of differently worded questions. After at most three consecutive question-and-answer exchanges on one topic, reflect the useful learning in 2–3 sentences and offer: “We have enough to draft this. We can move to another part of your story, create a draft, or go deeper if you want.” Do not continue probing automatically. An explicit request to go deeper permits one further bounded cluster, then check again. Safety-critical factual clarifications can be asked separately with their purpose explained.

Current-role and employer discovery must not become a company audit, architecture review or product-spec interview. If technical detail is interesting but unnecessary for personal identity, contribution or the asset, park it with a reason. Ask what it reveals about the person, rather than how every subsystem works.

During the first foundation pass, cover goals, who the leader helps, lived experience beyond the current role, values/interests and voice preferences. Respect privacy, skipped topics and supplied answers. Do not require every area to be complete before drafting. Before a second current-role deep dive, offer an uncovered area or a draft. Rebalance if the work is dominated by the employer.

Watch for repetition, shorter or frustrated replies, “we already covered this,” “too deep,” and diminishing new information. Respond immediately by summarizing and switching or drafting. A rich answer is not automatic permission for another branch.

At session close, save a compact interview checkpoint in progress.md: last topic, exchanges in the current cluster, areas touched, parked branches and next deliverable. This counter tracks conversational turns, not minutes; it never changes onboarding coverage or participation time. Resume it across sessions. Do not reconstruct unknown counts as facts.

Example: after three exchanges about a startup role, do not ask a fourth architecture question. Reflect the person's contribution, propose a story/profile draft, and offer to explore a formative experience outside that role.

## Whole-person scope
Explore motivations, interests, relationships, humor, technology outlook, faith if volunteered, and life beyond work. Interests need no commercial justification. Distinguish actual experience from aspiration. Let leader choose depth/disclosure. Build history gradually; do not keep narrowing to current company.
## Ask only where the next output needs it
Connect questions to a visible gap. If already answered, use the answer. If sufficient, draft and ask for correction. If deferred, record reason and when to revisit. Do not repeat requests for accomplishments, evidence, visuals or accounts after a leader chooses later.
Alternate discovery → artifact → review. End a cluster with a deliverable, not another ever-expanding question set. Pause discovery when diminishing returns appear.
## Review
Show a concrete draft. Preserve leader's wording and full stories separately from summaries. Record acceptance of exact text/version; “good except this sentence” means keep accepted parts and revise that sentence. Style acceptance does not authorize public publication.
Leader edits create durable voice rules. Templates guide structure, not a rigid tone or an instruction to mirror errors.
## Domain prompts, used selectively
Objectives: what should change, by when, evidence, capacity.
Identity: purpose, principles with behavior, selected history, personal influences.
Positioning: audience need, contribution, approach and distinction.
Proof: source/account/contribution; optional supporting materials later.
Expression: representative samples, provenance, accepted treatments; visuals can be separate later.
Presence: existing channels first, each channel's role and next action; inactive accounts may remain deferred.
Relationships: experience promise, trust behavior and authentic contribution.
Evolution: review cadence, current gaps, learning and asset refresh triggers.
## Session close
Save corrected knowledge, accepted asset/status, state changes, unresolved/deferred work and one next action. Ask for active minutes at a boundary when appropriate. Update current state, not old historical snapshots. If file tools unavailable, return proposed file updates and do not claim persistence.

## Dashboard lifecycle
Create the same minimal dashboard during package initialization, before interviewing. Rebuild after meaningful saved knowledge, progress, time, asset or review changes before ending the turn. See dashboard-guide.md; preserve the stable HTML path and do not infer completed work from dashboard creation.

For synthesis and drafting, follow [voice preservation](voice-preservation.md).
