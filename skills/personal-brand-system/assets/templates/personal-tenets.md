# Personal tenets
ID: personal-tenets | Version: 0.1.0
Audience/use: a leader's separate set of guiding principles and how they show up in practice.

## Generate
Reuse supplied values, stories and principles. Ask only for material gaps. Propose a small useful set in the leader's language; do not impose a required count, religious foundation or universal principles. A draft must say it is unreviewed. Explain each principle through a concrete behavior when useful.

Create a separate leader-prefixed, versioned output. Keep the purpose in its own asset, linked if helpful. Store personal-tenets in references/integrity-register.json as a language record: exact_text contains one tenet per line, optionally prefixed with '- '; source, version, disclosure and approval_status follow the integrity guide. Unreviewed is the default. Accepted output can resolve {{language:personal-tenets}} through scripts/render_asset.py for exact reuse.

## Explicit approval and overview
Only a leader's explicit approval of this tenet set changes its canonical record to accepted-for-reuse (or public-approved for a specific authorized context). The overview shows only the approved set; missing or unreviewed tenets produce no panel or empty placeholder. Approval of the purpose, the asset split or foundation checklist does not approve these principles. Asset index status alone does not activate the overview.

When revising an approved set, keep the last approved canonical wording until the replacement is reviewed; label the proposed revision separately. Preserve source wording, versions and scope. Private overview display is not public publishing authorization.

## Validate
Standalone tenet asset and canonical record match. No duplicated purpose section, unapproved overview text, fabricated scriptural attribution or assumed beliefs. If splitting an old combined asset, preserve its content/history, mark it superseded only after replacements exist, and retain separate approval states for purpose and tenets.
